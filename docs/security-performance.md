# セキュリティ・軽量化チェック（2026-11-21）

## セキュリティ

| # | 確認したこと | 結果・対策 |
| :-- | :-- | :-- |
| S-1 | 他人の記録を読み書きできないか | RLS で `user_id = auth.uid()` のみ許可。他人の `user_id` を指定した挿入が拒否されることを確認 |
| S-2 | ログインしていない状態で触れないか | `anon` ロールの権限を剥奪（RLS に加えて二重に閉じる） |
| S-3 | 開発用ログイン（匿名）が本番に出ないか | 本番ビルドでは環境変数に関係なく非表示。Supabase 側でも匿名ログインをオフにする手順を用意 |
| S-4 | 管理者キーの扱い | service_role キーは使わない。アカウント削除は `security definer` の DB 関数（`search_path` 固定）で本人のみ |
| S-5 | 外部サイトへの埋め込み・不正スクリプト | CSP（通信先を自分と Supabase に限定、`frame-ancestors 'none'`）、`X-Frame-Options: DENY`、`nosniff`、Referrer-Policy、Permissions-Policy、本番は HSTS |
| S-6 | 検索語による問い合わせの改変 | PostgREST の `or()` 構文を壊す文字を除去してから検索 |
| S-7 | 不正な値の保存 | DB 制約で拒否：ジャンルと種類の矛盾、未来すぎる日時、公開設定（共有機能ができるまで private のみ）、計測値の異常値、文字数・件数の上限 |
| S-8 | 大量登録による負荷 | フレーバーの言葉は1人1ジャンル100個まで |
| S-9 | URL パラメータの不正値 | 記録 ID は UUID 形式だけを受け付ける |
| S-10 | エラー文からの情報漏れ | 画面には DB のエラー文を出さない |
| S-11 | 依存パッケージの脆弱性 | `npm audit`：0件 |
| S-12 | DB の設定ミス | `supabase db lint`：指摘0件 |

残る注意点：Next.js のインラインスクリプトのため CSP に `'unsafe-inline'` が要る。ユーザー入力は React がエスケープし、`dangerouslySetInnerHTML` は固定文字列（テーマ初期化）だけに使っている。

## 軽量化

| # | 内容 |
| :-- | :-- |
| P-1 | サーバーでのログイン確認を `getClaims` に変更（署名の検証だけで済む場合は Auth サーバーへの往復なし）。1リクエスト内で結果を使い回す |
| P-2 | 取得する列を画面で使うものだけに絞った（`user_id`・計測値などは送らない） |
| P-3 | 「よく飲むもの」の集計を、記録数の2乗から1回の走査に |
| P-4 | 画面遷移中は骨組み（loading）を即座に出し、押した反応を見せる |
| P-5 | 保存は通信を待たずにシートを閉じて結果を表示（楽観的更新） |
| P-6 | アイコン画像に1週間のキャッシュ |
| P-7 | 外部フォント・UI ライブラリなし（システムフォント、素の CSS） |
